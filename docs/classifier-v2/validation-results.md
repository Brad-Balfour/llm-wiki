# Classifier v2 validation results

## September 6, 2026 blind check

The first final-check run compared the installed profile 1.4 and classifier
instructions v1 with candidate profile 2.0 and classifier instructions v2. Brad
labeled 20 distinct articles representing 21 newsletter occurrences without
seeing either prediction set.

Profile 2.0 matched the baseline's three false skips, two unwanted in-depth
decisions, and nine lower-harm interest disagreements. It introduced one missed
depth decision that the baseline did not have. Profile 2.0 therefore did not
meet the no-worse acceptance bar and was not installed.

The regression exposed an ambiguous boundary between generic unused tools or
local-model announcements and practical browser-native AI runtime engineering.
Candidate profile 2.1 makes the positive browser architecture and deployment
case explicit while preserving the negative prior for bare repositories and
model announcements. It also clarifies the existing negative prior for routine
new-model benchmark comparisons.

The September 6 material is now development evidence. Profile 2.1 requires a
new unseen final-check sample plus the combined Project commute before release.
The live Project and weekday Task remain unchanged until Brad approves and
confirms installation.

After applying the 2.1 rules, a fresh Project chat rescored the same now-known
development set. Relative to the baseline, false skips fell from three to zero,
unwanted in-depth decisions fell from two to zero, missed depth remained zero,
and lower-harm interest disagreements fell from nine to six. This confirms that
the corrections affect the intended cases, but it is not an independent release
result because the labels informed profile 2.1.
